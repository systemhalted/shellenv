Per-project shell sandboxes.

shellenv pins the shell version and option profile a project expects. shellenv exec runs a command with HOME, TMPDIR and XDG_* writes redirected into the project, so your shell session and real home stay as they were.

Install GitHub
  • Builds bash and zsh runtimes
  • Activates bash, zsh and fish sessions
  • Optional Docker or Podman mode
  • Written in Go, MIT licensed

In transcripts, $ marks a command, out marks stdout and err marks stderr.

What gets pinned

One script can behave differently across shells. Each project env lives in ./.shellenv/<env>/. It records a shell and a profile, and it has its own bin/ and sandbox home/.

Shell runtime

shellenv install builds bash or zsh from the official source tarball. bash@5.2, bash@3.2.57 and zsh@5.9 have pinned SHA-256 checksums. Other versions install with an unverified-download warning, or fail up front with --require-checksum.

Option profile

strict (set -euo pipefail), posix (set -o posix) or interactive. Fish sessions source a .fish variant of the profile; shellenv doesn't install fish itself.

PATH

The env's bin/ comes first, then the installed runtime's bin/, then your usual PATH. A tool dropped into bin/ shadows the system copy.

Home and temp dirs

HOME, TMPDIR, XDG_CONFIG_HOME, XDG_CACHE_HOME, XDG_DATA_HOME and XDG_STATE_HOME point into the env's sandbox home/. exec always does this; activate does it with --isolate-home.

Three ways to run

All three put the env's bin/ first on PATH. They differ in how far the isolation goes. Each picks the env you name, else ./.shellenv/current (set by shellenv use), else default.

activate

For an interactive session with the env's tools and profile at your prompt. Undo it with eval "$(shellenv deactivate)".

Fish pipes the snippet instead of using eval:

exec

For one-off or scripted runs. Writes to $HOME and temp files land in the sandbox, and the command's exit status is passed through. Add --ephemeral for a sandbox home that is deleted after the run.

exec --container

For scripts that change the system. Runs in Docker or Podman, whichever is on PATH, with the project directory mounted at the same path. The image supplies the shell, so --strict-shell is rejected here.

Scope. Host mode (activate and exec) is a user-space sandbox. exec always keeps writes out of your real home; activate does so only with --isolate-home. Host mode is not a security sandbox for untrusted code: the network, processes and the rest of the filesystem are shared. Only exec --container adds namespace isolation. ARCHITECTURE.md lists exactly what is and isn't isolated.

Walkthrough

From an empty project directory, with SHELLENV_HOME pointed at a temp directory so nothing touches ~/.shellenv. Output is from a real run, with paths shortened to …/.

  1. Create the global home

    init sets up $SHELLENV_HOME (default ~/.shellenv) with installs/, cache/ and tmp/.

  2. Declare the shell and profile

    create writes ./.shellenv/default/ with metadata.json, bin/ and home/.

  3. Build the runtime

    install downloads the source tarball, checks its SHA-256 and builds it, once per version. You can skip it: commands then run on the system shell with a warning.

  4. Run commands with exec

    With the runtime installed, the warning is gone. HOME and TMPDIR point into the sandbox.

    --profile sources the strict profile first. Its set -e applies to what that shell runs directly, so source the script with . to test it under the profile. A script run through its own shebang starts a fresh shell and gets only the profile's exported variables.

  5. Activate, then deactivate

    activate prints a snippet for your shell to eval. deactivate restores PATH, the prompt and any isolated variables, and unsets SHELLENV_*.

    It can't undo shell options. After the strict profile, set -euo pipefail stays on in that shell, so a failing command will close it. Use a throwaway shell for this.

Install

shellenv is a single Go binary for Linux and macOS.

From a release

Download the tarball for your platform from the releases page and check it against SHA256SUMS. Replace <version> below with the release you downloaded.

  • Keep the binary next to its bundled profiles/ directory. If you move or symlink the binary alone, set SHELLENV_PROFILES to that profiles/ directory.
  • Man pages are in man/. Read a man page in place with man -l man/shellenv.1.

From source

Needs Go 1.22 or later and make.

  • The binary lands in ./dist/shellenv. Run it from the checkout and it finds the built-in profiles in ./profiles.
  • shellenv install needs a C compiler, make and tar, and takes a few minutes once per version. shellenv doctor checks for them.
