01 / The idea

Your project sets the rules.

One script can behave differently across shells. Make those differences explicit, then test them without rearranging your login shell.

[ 01 ]

Declare the runtime

Record the shell and version your project expects. Install Bash or Zsh from source, then use --strict-shell to require that runtime.

bash@5.2 · bash@3.2.57 · zsh@5.9
[ 02 ]

Choose the conditions

Try strict, POSIX, or interactive profiles. With --profile, the profile is sourced first and its options govern what that shell runs directly, such as a sourced script.

shellenv exec --profile -- . ./probe.sh
[ 03 ]

Contain the clutter

Host execution redirects HOME, TMPDIR, and XDG_* paths into your environment. Use a throwaway home when you want a fresh start on every run.

shellenv exec --ephemeral -- ./probe.sh

02 / Pick your workflow

One environment. Three ways to work.

Stay interactive, run a single command, or add container namespaces. Choose the boundary your experiment needs.

A focused run

Run it. Keep the result.

Execute a command in a subprocess with a sandbox home. Your current shell session stays as it was, and the command's exit code carries through to CI.

host mode
$ shellenv exec -- ./run-tests.sh
Add --ephemeral to delete the sandbox home after the run.

An interactive session

Step inside.

Activate the environment in your current shell to get its tools, runtime, and profile at your prompt. Add --isolate-home to sandbox writes to ~ too, and deactivate to put everything back.

bash / zsh
$ eval "$(shellenv activate --isolate-home)"
$ eval "$(shellenv deactivate)"

Real isolation

Put a wall around it.

Run the command inside a Docker or Podman container with the sandbox home mounted. Use it for scripts that install packages or otherwise change the system. The image supplies the shell.

container mode
$ shellenv exec --container ubuntu:22.04 -- ./install.sh
--strict-shell is host-only; pick an image that provides your shell.
Container: boundaries at a glance

Know the boundary. Host mode is a user-space sandbox, not a security sandbox for untrusted code. Network, processes, and the wider filesystem remain shared. Container mode adds namespace isolation.

03 / Start small

Your first sandbox is a few commands away.

Build from source with Go 1.22+ and make, or download a platform tarball from GitHub Releases.

Browse releases →

Using a release? Verify the archive against SHA256SUMS. Keep the binary beside its bundled profiles/ directory, or set SHELLENV_PROFILES.
FROM SOURCE
git clone https://github.com/systemhalted/shellenv.git
cd shellenv
make build

./dist/shellenv init
./dist/shellenv create --shell bash@5.2 --profile strict
./dist/shellenv install bash@5.2
./dist/shellenv exec --strict-shell -- printenv HOME
Installing a runtime needs a C compiler, make, and tar, and takes a few minutes once per version. Without an installed runtime, host mode falls back to the system shell with a warning unless you pass --strict-shell.
